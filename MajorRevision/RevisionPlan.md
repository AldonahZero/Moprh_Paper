## 6. 版本与提交流程

可以直接修改 LaTeX。建议按以下顺序组织：

1. **固定真正投稿基准。** 从实际上传的 PDF、对应源文件或 Git 提交确认版本，保留全部 `.tex`、`.bib`、图片、类文件及所需依赖。当前 HEAD 只作为工作现场记录。
2. **在修订分支修改干净源码。** 优先完成 M1–M4，同时逐条处理 A/B/C；正常用 Git 记录每组修改。
3. **同步维护回复信。** 开头概括主要修改，再按 metareview 四项和 A/B/C 各意见回应。每条写“问题—实际修改—页码/节号/表号—证据或剩余限制”。最后统一页码，避免只写将来会修改。
4. **整合已核验数据，补做必要实验。** 先确定事实和可支撑的结论，再更新摘要、贡献列表和实验结论。
5. **编译干净修订 PDF。** 核对布局、引用、数字、匿名性及页数。
6. **从原始投稿源码与最终修订源码生成标色差异 PDF。** 可用 latexdiff；普通 `git diff` 用于源码检查。多文件、宏和替换图片的差异需人工检查，图片内容变化应在图注或回复中明确指出。
7. **提交三份核心材料并更新 artifact。** 准备干净修订 PDF、标色差异 PDF、Author Response；实际上传字段、文件命名和任何单独页数要求以决定信和 HotCRP 为准。

建议目录职责：

| 内容 | 用途 |
| --- | --- |

| 修订源码 | 唯一维护的正文版本 |
